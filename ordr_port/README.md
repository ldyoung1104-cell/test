# ORDR 모드 이식 도구

## 자동 패치 (새 버전이 나왔을 때)

### 처음 한 번 준비
1. https://www.python.org/downloads/ 에서 파이썬 설치.
   설치 첫 화면 아래 **"Add python.exe to PATH"** 에 체크하고 설치.
2. 이 저장소 zip 을 받아 풀고, `ordr_port` 폴더를 원하는 곳에 둔다.
   (다른 프로그램 설치는 필요 없음. StormLib.dll 도 필요 없음)

### 사용
1. 새 버전 원본 맵(예: `ORDR_S2_2.324[C].w3x`)을 `ordr_port` 폴더 안의 **`ORDR_patch.bat` 위로 끌어다 놓는다.**
2. 검은 창에서 20~30초 정도 진행된 뒤 결과가 나온다. 맵과 같은 폴더에 생기는 파일:
   - `..._mod.w3x` : 기능이 들어간 맵 (성공했을 때만)
   - `..._mod.j` : 기능이 들어간 스크립트
   - `..._report.txt` : 보고서
3. **"결과: 성공"** 이면 `_mod.w3x` 로 플레이하면 된다.
   **"결과: 오류"** 면 맵은 만들어지지 않는다. `_report.txt` 와 원본 맵을 Claude 에게 보내 물어보면 된다.
4. 성공하면 그 버전이 `ref/<버전>/` 에 저장되어 다음 버전은 그것을 기준으로 삼는다.

명령창에서 직접: `python ordr_patch.py "ORDR_S2_2.324[C].w3x"`

### 주의
- 반드시 **공식 배포된 원본 맵**을 넣는다. 이미 기능이 들어간 맵을 넣으면 멈춘다.
- 보고서에 "새로 생긴 조합법" 경고가 있으면 새 유닛이 자동조합 목록에 아직 없다는 뜻이다
  (맵은 정상 동작). 목록 갱신은 Claude 에게 요청.
- 원본 코드가 크게 바뀐 곳은 "위치를 못 찾음" 오류로 알려 준다. 조용히 틀리게 넣지 않는다.

### 기능 추가
`ref/<버전>/base.j`(원본)와 `ref/<버전>/mod.j`(원본 + 기능)의 **차이 전체**가 옮겨진다.
새 기능은 최신 `mod.j` 에 추가하면 다음 버전부터 자동으로 따라간다.
새 함수를 추가하고 원본에는 호출 한 줄만 거는 방식이 가장 잘 옮겨진다.

### 검증한 것 (새 버전이 없어서 아래로 대신 확인)
- 2323 원본 → 결과가 배포한 2323 결과물과 바이트 단위로 같음
- 실제 버전 차이: 2323 기능을 2322 원본에 이식 → pjass 통과, 경고 목록이 원본과 같음
- 가짜 2.324: 난독화 이름 6288개 무작위 변경 + 함수/전역 삽입 + 상수 변경 → 이식 성공, pjass 통과.
  그 결과를 기준으로 다시 2323 에 이식하면 배포한 결과물과 바이트 단위로 같음 (왕복 검증)
- w3x 읽기/쓰기(`mpq_pure.py`): 맵 4개에서 StormLib 과 같은 내용을 읽고,
  쓴 맵을 StormLib 으로 다시 읽어도 같음. 다른 파일은 그대로
- 이미 패치된 맵을 넣으면 맵을 만들지 않고 멈춤
- 윈도우 PC 에서 직접 실행해 보지는 못함 (이 환경은 리눅스)

## 2323 결과물 (`output/2323/`)

- `war3map.j` : 2323 원본 j + 아래 기능
- `ORDR_S2_2.323[C]_mod.w3x.part0/1` : 완성된 맵 (GitHub 100MB 제한 때문에 분할).
  같은 폴더에서 `join.bat` 실행 → `ORDR_S2_2.323[C]_mod.w3x` 생성
  (sha256 `aa450fd4e755bca113dd87433fdbdb9828990c0a57872f2141fc02f5af63d5c3`)

### 들어간 기능 (2322 수정본에서 이식)
| 기능 | 명령 |
|---|---|
| 자동조합 (조합 도우미 UI, 새로 작성) | `I` 키 / `-자동조합` / `Esc` 닫기 |
| 로또모드 | `@로또모드`, `@로또1`~`@로또9`, `@로또자동` |
| 위습 자동 이동 | `@위`, `@취소` |

### 조합 도우미 UI (`mods/autocombo_ui.j`)
- 등급 탭 17개(전체 + 16등급, 유닛 수 표시), `조합 가능만` / `진행률순 정렬` 필터, 20개씩 페이지
- 카드: 아이콘, 등급색 이름, 보유 수, 진행률 바와 상태
  (초록 = 바로 조합, 노랑 = 하위 조합으로 가능, 회색 % = 진행 중, 보라 = 특수 조합)
- 진행률: DRD96 방식. 레시피를 하위 재료까지 펼친 기본 재료 수 중 보유한 비율
  (가진 유닛은 중복 계산하지 않음)
- 상세: 큰 아이콘, 등급, 보유 수, 진행률, 필요 조건 전부(유닛/골드/목재/특성포인트/아이템/특수조건).
  재료 줄 클릭 → 그 재료의 조합법으로 이동, `< 뒤로`로 복귀
- 상세 창 아래 **부족한 최하위 재료** 한 줄: 레시피를 끝까지 펼쳐 가진 유닛을 뺀 뒤 모자라는
  조합 불가 유닛(흔함 등)을 `해군 칼병 x3, 해군 총병 x1` 형식으로 표시
- `자동조합 실행`: 부족한 재료를 하위 조합부터 순서대로 자동 조합 (기존 로직)
- 열려 있는 동안 1초마다 갱신
- I 키 수정: UI 를 맵 로딩 중이 아니라 게임 시작 0.5초 뒤에 만들고, 채팅 입력 판정이
  Enter 한 번에 영구히 꼬이지 않게 30초 후 자동 해제

`apply_autocombo_ui.py 입력.j 출력.j 맵.w3x` 로 이식된 j 에 적용한다.

### 10차 파일에 부족한 최하위 재료 표시만 적용하기
`output/2323/missing_leaf.patch` 는 이 기능 변경분만 담고 있다. 10차 j 파일 이름을 `war3map.j` 로
바꾼 폴더에서 `git apply missing_leaf.patch` (Git for Windows) 로 적용.

### 넣지 않은 것
- 이지모드 (`@이지모드`, `@세이브3000`) — 요청으로 제외
- 무결성/복제맵 검사 우회, 자동로그인 후 스탯 덮어쓰기, 스킨·치장 강제 해제
- 2322에 있던 도박 확률 100% 변경 (요청 목록에 없음)

> 2323 원본의 수정 감지(핸들 ID 검사)는 그대로 두었습니다. 추가 코드가 핸들을 만들기 때문에
> 맵이 수정본으로 감지되어 로그인/세이브가 동작하지 않을 수 있습니다.

## 도구

- `jass_port.py` : 이식 엔진. 난독화 이름이 바뀐 두 버전의 j 를 정렬하고,
  같은 줄에서 이름 변환표(예: `BD2 -> BD6`)를 만들어 모드 코드를 새 이름으로 옮긴다.
  이름 종류/타입 불일치, 변환표에 없는 이름, 선언 누락, 이름 충돌을 검사한다.
- `build_2323_from_2322.py` : 2322 수정본 → 2323 1회용 스크립트
  (2322 원본이 없어 수정본에서 모드 줄을 지운 것을 가상 원본으로 사용).
- `mpq.py` : StormLib 으로 w3x 안의 파일을 꺼내고(`get`) 바꿔 넣는(`put`) 도구.
  `STORMLIB` 환경변수로 libstorm 경로 지정.

```
python build_2323_from_2322.py 2322수정본/war3map.j 2323원본/war3map.j out.j
python mpq.py put 맵.w3x war3map.j out.j
```

### 검증 (2323)
- 이식에 쓰인 원본 함수 26개/전역 112개 모두 2322↔2323 본문·타입 일치 (확신도 100%)
- 자동조합이 복사해 둔 조합 후처리 함수 114개 모두 2323에서 변경 없음, 조합법 266개 동일
- if/loop/function 짝, 함수 정의-사용 순서, 참조 파일(아이콘/사운드/폰트) 존재 확인
- 2323 원본 대비 삭제된 줄 0, 추가만 있음
- 자동조합 함수의 지역변수 60개가 2323 전역(다른 타입)과 이름이 겹쳐 맵 로드가 실패하던 문제 수정
  (`Ys` → `ml_Ys` 등). pjass 검사 결과가 2323 원본과 동일
- 새 UI 모듈 적용 후에도 pjass 문법 검사 통과, 경고 목록이 2323 원본과 동일
- 실제 게임 실행 테스트는 하지 않음
